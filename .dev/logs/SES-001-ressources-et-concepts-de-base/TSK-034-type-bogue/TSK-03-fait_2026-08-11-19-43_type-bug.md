# Ce qui a été fait, tâche 34

`MET-003` étape 3.

## La définition, tirée de sept cas réels

Le dépôt porte sept écarts constatés en trois jours. Ils fondent la définition.

| Date | Écart | Règle enfreinte |
|---|---|---|
| 08-09 | 14 ADR archivés comptés parmi 3 actifs | Les archives portent l'état révolu |
| 08-10 | Gabarits comptés comme instances | `RES-001` les place hors du modèle |
| 08-10 | `type: 009` au lieu de `type: decision` | `ADR-007` |
| 08-11 | Nommage daté pour les point-fixe | `ADR-007` D4 |
| 08-11 | `clia git save` cassé par le nouveau nommage | `MET-003` C4 |
| 08-11 | Un test codifiait le bogue du nommage | `ADR-007` D4 |
| 08-11 | Le statut affiché n'apprend rien | `PDC-001` |

**Les sept partagent une chose, sans exception.** Chacun est un écart entre un comportement attendu et un comportement constaté, et l'attendu vient d'une **règle écrite**.

C'est la définition retenue : **sans règle de référence, il n'y a pas de bogue**.

## Ce qui départage le bogue de ses trois voisins

| Voisin | Ce qui départage |
|---|---|
| `ISU` | L'issue n'a **aucune règle de référence** |
| `CMP` | Le comportement dit ce qui **doit** être ; le bogue dit ce qui **n'est pas** |
| `NON` | L'objection **conteste** une règle ; le bogue constate qu'elle **n'est pas tenue** |

**La frontière avec l'objection est la plus utile.** `NON-005` conteste depuis le 2026-08-09 l'accumulation de règles écrites et non tenues. Un bogue est le cas particulier d'une de ces règles, constaté sur un objet précis.

**Ce que cela implique.** Un bogue est plus SMART qu'une issue : il a une règle, donc un critère, et il est reproductible, donc vérifiable. C'est ce qui justifie un type distinct.

## Deux rubriques obligatoires, et leur motif mesuré

**« La cause ».** Sur les sept cas, **la cause diffère du symptôme dans cinq**. Le symptôme du troisième était `type: 009` ; la cause était que le générateur dépendait de l'`id`, dont la forme avait changé.

**« La correction » dit si un contrôle existait.** Le sixième bogue était protégé par un test qui codifiait l'ancien comportement et passait au vert pendant deux jours. **Un contrôle peut cacher un défaut au lieu de le détecter.**

## Le champ `etat`, et sa valeur la moins évidente

| Valeur | Ce qu'elle affirme |
|---|---|
| `ouvert` | L'écart subsiste |
| `corrige` | L'écart ne se reproduit plus, et un contrôle le vérifie |
| `non-reproduit` | L'écart n'a pas pu être reproduit |
| `accepte` | L'écart subsiste et il est assumé |

**`accepte` n'est pas `corrige`.** Un bogue accepté reste un écart : le déclarer évite qu'il soit redécouvert et retraité.

**L'agent ne peut pas poser `accepte`.** Accepter un écart est une décision, et `CONSTITUTION.md` C1 la réserve à l'humain.

## Un choix de modèle, déclaré

`DCN-016`, produite hier, remplacerait `status` et les huit champs propres par quatre champs. **Elle porte `effet: suspendue`.**

`RES-036` suit donc le modèle **en vigueur** : `status` plus un champ `etat` propre.

**Le motif.** Créer un type sous un modèle non approuvé forcerait la main sur `DCN-016`. `PLN-007` chantier D portera la migration des cent cinquante-huit instances, celle-ci comprise.
